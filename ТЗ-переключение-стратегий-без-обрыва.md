# ТЗ: Маскировка переключения стратегий zapret под кратковременный «провал» интернета

**Версия:** 1.0 (черновик)
**Статус:** на согласование
**Проект:** Integra 3 (crates/zapret, crates/app)

---

## 1. Контекст и проблема

При переключении стратегии zapret (смена активностиgeneral*.bat` → рестарт `winws.exe`) текущая механика Integra делает **стоп → старт**. В итоге:

- сайты, попадающие под DPI, **теряют соединение** и просят переподключиться;
- в играх пользователя **выкидывает из лобби / активной игры**;
- в момент стопа трафик на 1–2 сек идёт без фильтрации.

Пользователь просит **замаскировать** переключение под кратковременный провал интернета: на время перезагрузки `.bat` и zapret (защита 2–3 сек) исходящий трафик временно «замораживается», затем размораживается. Приложения должны воспринимать это как обычную паузу сети (джиттер/тишину), а не как обрыв.

## 2. Цель

Обеспечить переключение стратегий zapret без потери активных соединений (сайты, игровые лобби) за счёт временной полной заморозки исходящего трафика на время рестарта `winws.exe`.

## 3. Существующая механика (база)

- `manager.rs`: `stop()` (завершение дерева процессов `winws` через Toolhelp32) и `start(&strategy_file)` (генерация runtime-BAT через `runtime_bat.rs`, запуск скрытого `cmd.exe`).
- `benchmark.rs`: перебор стратегий «стоп → старт → прогрев → проверки → скоринг», восстановление исходного состояния.
- UI: выбор стратегии в выпадашке (карточка профиля), `start_profile(profile_id, strategy)`.
- Права администратора (UAC) уже требуются для запуска winws/WinDivert.

## 4. Предлагаемое решение

«Шлюз» на уровне фаерволла вокруг рестарта:

1. **Заморозить** исходящий трафик: `netsh advfirewall set allprofiles firewallpolicy blockoutbound` (входящий не трогать).
2. **Переключить**: стоп старого `winws` → генерация runtime-BAT → старт нового → ожидание живого PID.
3. **Разморозить**: восстановить прежнюю политику (`allowoutbound`) **только после** подтверждения, что новый процесс жив.
4. **Watchdog**: если за N сек (по умолчанию 4) новая стратегия не взлетела — принудительно разморозить (иначе пользователь останется без сети вообще).

### Почему это сработает

- TCP-серверы интерпретируют 2–3 сек тишины как штатную задержку (ретрансмит-таймаут ~1 сек, сдача соединения — десятки секунд).
- UDP-лобби (голос, гейм-серверы) обычно переживают 2–3 сек тишины.
- Заморозка убирает и «голый» трафик в момент стопа (побочный плюс).

## 5. Требования

### 5.1 Функциональные

- **F1.** Перед каждым рестартом стратегии (ручное переключение, старт профиля с другой стратегией, бенчмарк) исходящий трафик блокируется.
- **F2.** Порядок: блокировка → стоп → старт → проверка живости PID → разблокировка.
- **F3.** Если разблокировка не выполнена по любой причине — watchdog разблокирует не позже, чем через `mask_timeout_ms` (по умолчанию 4000).
- **F4.** Блокируется только исходящий трафик (outbound); политика входящего не меняется.
- **F5.** Заморозка применяется только если профиль был запущен (иначе просто старт без маски).
- **F6.** Флаг в конфиге: `profile.mask_strategy_switch` (по умолчанию true) — возможность отключить маску.
- **F7.** Событие в UI: «Переключение стратегии… интернет замёрзнет на 2–3 сек» (тост/статус).

### 5.2 Нефункциональные

- **N1.** Полное время заморозки — ≤3 сек при штатном рестарте (2 сек запас на watchdog).
- **N2.** Маска не должна применяться при `stop_profile` (простое выключение).
- **N3.** Не использовать сторонние зависимости; только `netsh advfirewall` (уже доступен на Windows).
- **N4.** При отсутствии прав администратора — маска пропускается с warning-логом (защита от полной блокировки сети).
- **N5.** Код покрыт юнит-тестами (быстрый тест на эмуляции политики; интеграционный — ручной).

## 6. Точки интеграции

| Файл | Что меняется |
|---|---|
| `crates/zapret/src/manager.rs` | Обвязка `switch_strategy()`: заморозка → стоп → старт → разморозка; watchdog |
| `crates/zapret/src/lib.rs` | Доступ к политике из app-слоя |
| `crates/app/src/lib.rs` | Команда `switch_profile_strategy` (или доработка `start_profile`); событие в UI |
| `crates/app/src/benchmark.rs` | Использовать тот же `switch_strategy()` вместо «стоп → старт» |
| `crates/core/src/config.rs` | Новое поле `mask_strategy_switch` |
| `crates/app/ui/js/app.js`, `index.html` | Тосты + переключатель маски в настройках профиля |

## 7. Параметры (по умолчанию)

| Параметр | Значение | Пояснение |
|---|---|---|
| `mask_timeout_ms` | 4000 | Максимум до принудительной разморозки |
| `mask_allow_seconds` | 3 | Целевое время штатной заморозки |
| `mask_policy` | blockoutbound | Блокируется только исходящий |

## 8. Краевые случаи и защита

- **Новая стратегия не запустилась** (битый `.bat`, нет прав): разморозка обязательна; в лог — ошибка; профиль остаётся в состоянии «остановлен».
- **Аварийное падение Integra** во время заморозки: watchdog-таймер работает в отдельном потоке и переживает падение основного (разморозка через `netsh` в отдельном процессе).
- **Пользователь вручную отключил фаерволл/изменил политику** во время маски: разморозка восстанавливает ту политику, что была до заморозки (сохранить и восстановить, не хардкодить allow).
- **Множественные переключения подряд** (бенчмарк): маска применяется на каждый шаг, но watchdog не накапливается (серийно).

## 9. Критерии приёмки

1. Ручное переключение стратегии в UI: сайт, висящий под DPI, **не** просит переподключиться; лобби игры не выкидывает.
2. Во время переключения (2–3 сек) `ping` извне не проходит, после — восстанавливается.
3. Имитация сбоя (убить новый winws до разморозки): через ≤4 сек сеть автоматически восстанавливается.
4. С `mask_strategy_switch=false` поведение — как сейчас (без маски).
5. Бенчмарк проходит без потери сети после прогона.
6. Юнит-тесты N5 зелёные.

## 10. Не входит в объём (out of scope)

- Шифрование трафика / анонимность (это не цель маски).
- Автоматический подбор стратегии по типу блокировки.
- Маскировка для Linux-версии (nfqws).
