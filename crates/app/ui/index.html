Анализ: «белые списки» интернета в РФ

Как устроена фильтрация и чем лечится каждый её режим (по материалам проекта whitelist-bypass, сентябрь 2026)

Проверка интернета

Быстрый тест: работает ли сеть, режет ли DNS, есть ли заморозка по объёму или режим белого списка.

Три уровня фильтрации — не путайте их

УровеньЧто фильтруетсяКак выглядит сбойЧем лечится
1. SNI/Hostимя сайта в TLS ClientHello или HTTP Hostсайт не открывается, соединение рвётся / RSTфрагментация пакетов (sniproxy), подмена SNI, DoH
2. Объём на сессиюбайты в одной TCP-сессиистраница грузится и замирает после ~16 КБ, разрыва нетцепочка через РФ-узел, ротация соединений (chain-relay burst)
3. IP/CIDR/ASNадрес назначения, целые автономные системытаймаут, пакеты не идут вообщетолько узел на «белом» IP внутри РФ

Главная ошибка — лечить уровень 3 инструментами уровня 1: если фильтрация по IP, соединение дропается до разбора SNI.

Что делать в каком режиме

ВердиктДействие
CLEANограничений нет — ничего не нужно
BLACKLISTобычный чёрный список по доменам → sniproxy (tls-split), DoH
FREEZE16K / REGISTRY_SZSзаморозка по объёму → цепочка из 3 узлов (РФ-мост → выходная нода), chain-relay burst для больших файлов
HARD_WHITELIST / DROP_ALLфильтрация по IP/ASN → нужен узел на «белом» IP внутри РФ; проверьте свою AS (wlprobe asn)

Честные ограничения

  • Надёжного способа сохранить доступ в режиме реестра СЗС нет — фильтрация бьёт по инфраструктуре самих средств обхода.
  • Поиск «белого» IP в российских облаках — лотерея: списки меняются, держите запасной узел.
  • Даже разрешённое работает нестабильно: доля успешных соединений в режиме реестра ≤ ~10%.
  • Белые списки различаются у операторов — проверяйте каждый канал отдельно.
  • Проводной доступ пока почти не затронут.

Правовые риски (кратко)

Использование VPN физлицом отдельной ответственности не влечёт; реклама VPN-сервисов — штрафы; хостинг узла обхода на территории РФ — отдельная зона риска. Это не юридическая консультация.
